# 学生向け AI 駆動グラフィックスプログラミング演習プログラム

## Description

SIRIUS のポストエフェクト機構を題材に、AI 駆動開発（AI-DLC）の体験・コードレビューの必要性・ビジュアルリグレッションテストとパフォーマンステストの価値を実体験できる学生向けグラフィックスプログラミング演習プログラムを作成する。

演習は 3 パートで構成する:

1. **座学（テキスト教材）**: AI-DLC の概念（従来の「人間が書く → AI が補助」から「AI が提案 → 人間が承認・レビュー」への主従逆転）と、AI 生成コードへのレビューが不可欠な理由を説明する。

2. **新規実装演習（RotationBlur）**: 既存の `RadialBlur` を参照しながら「画面中心を軸に回転するブラーエフェクト」を AI 駆動で新規実装する。AI が意図的に 2 種類のバグを含むコードを生成するシナリオとし、受講者が問題点を指摘・修正しなければ完成しない設計にする。

3. **改修演習（DirectionalBlur 高品質化）**: 既存の `DirectionalBlur` に対して「より高品質なサンプリング」を AI 駆動で改修する。AI が意図的にパフォーマンス悪化とビジュアルデグレを引き起こすコードを生成するシナリオとし、受講者がパフォーマンステスト・ビジュアルリグレッションテストを実施することで問題を発見させる。

各演習は「問題入りスキル（Claude Code スキル）」と「正解コード」を事前に用意し、全受講者が同一の結果に到達できることを担保する。演習で AI にコードを書かせる体験自体は提供しつつ、最終的な答えはスキルの中に事前埋め込みで統一する。

## Context

### 配置先パッケージ・ファイル構成

- 演習素材（テキスト・スキル・正解コード）は `docs/workshop/` 以下に配置する
- 問題入りスキルは `.claude/skills/workshop-rotation-blur/` および `.claude/skills/workshop-directional-blur/` に配置する
- 演習で実装するシェーダーの正解コードは `docs/workshop/answers/` に配置する（`Sirius.PostProcessing` への本番マージは想定しない）

### 受講者想定

- Unity の基礎知識はあるが、HLSL / URP ポストエフェクトのパイプラインは未経験〜初心者
- `Vertex / Fragment Shader` の概念は把握しているが、モバイル向けの精度最適化や UV 空間の縦横比補正は未経験

### 演習で扱う機能

| パート | 機能 | 参照コード |
|---|---|---|
| Part 2（新規実装） | RotationBlur（回転ブラーエフェクト） | `RadialBlur.shader`（コード構造が類似） |
| Part 3（改修） | DirectionalBlur 高品質化 | `DirectionalBlur.shader`（既存コード） |

#### Part 2（RotationBlur）AI バグ設計

| バグ種別 | 内容 | 検出方法 |
|---|---|---|
| 視覚的バグ | アスペクト比補正なし。横長画面で楕円形のブラーになる | 目視で即気づける |
| パフォーマンスバグ | UV・方向ベクトルの計算に `half` でなく `float` を使用 | モバイル GPU 負荷静的解析で検出 |

正解の要点: 接線方向ベクトルに `half2(_ScreenParams.y * rcp(_ScreenParams.x), 1.0)` を乗算してアスペクト比補正を行い、全計算を `half` 精度で実施する。

#### Part 3（DirectionalBlur 改修）AI バグ設計

| バグ種別 | 内容 | 検出方法 |
|---|---|---|
| パフォーマンスバグ | サンプリング数を増やし `UNITY_UNROLL` を外して動的ループ化 | モバイル GPU 負荷静的解析で検出 |
| ビジュアルデグレ | 合成式の変更（`rcp(sample_count)` の代わりに定数除算を使用） | ビジュアルリグレッションテストで差分検出 |

正解の要点: サンプリング数および `UNITY_UNROLL` は既存コードを維持し、合成式も既存ロジックを踏襲する。

### 動的軸

静的（演習素材自体はランタイム変更なし。RotationBlur / DirectionalBlur は実行時ポストエフェクトだが、演習プログラムとしての制御は Inspector で事前設定する想定）。

### 背景となる依頼

「AI 駆動開発によるグラフィックスプログラム入門」ワークショップの演習プログラム作成。受講者全員が同じ結果に到達できるよう、AI が「間違いコードを生成する」シナリオを事前に用意しておき、受講者は答えを知らない状態で AI と協働しながら問題を発見・修正する体験を積む。

## Completion Criteria

### ✅ 成功ケース

**Part 1（座学テキスト）**
- `docs/workshop/01_intro_ai_dlc.md` に AI-DLC の概念説明テキストが揃っている
- AI がなぜ間違えるか・なぜレビューが必要かをコード例付きで説明している

**Part 2（RotationBlur 新規実装演習）**
- `.claude/skills/workshop-rotation-blur/SKILL.md` が存在し、AI がアスペクト比補正なし + `float` 精度の RotationBlur コードを生成するシナリオが機能する
- 正解の `RotationBlurPass.shader` と `RotationBlurRenderPass.cs` が `docs/workshop/answers/` 以下に揃っている
- 問題入りコード（アスペクト比補正なし）を横長画面で実行すると、ブラーが楕円形になることを目視確認済み
- 問題入りコード（`float` 精度）をモバイル GPU 負荷静的解析にかけると、正解コードよりレジスタ使用数またはサイクル数が悪化することを確認済み

**Part 3（DirectionalBlur 改修演習）**
- `.claude/skills/workshop-directional-blur/SKILL.md` が存在し、AI がサンプリング数増加 + 合成式変更の改修コードを生成するシナリオが機能する
- 正解の改修後 `DirectionalBlur.shader` が `docs/workshop/answers/` 以下に揃っている
- 問題入りコード（動的ループ）をモバイル GPU 負荷静的解析にかけると、正解コードより悪化することを確認済み
- 問題入りコード（合成式変更）でビジュアルリグレッションテストを実行すると、既存スナップショットとの差分が検出されることを確認済み

### ❌ 失敗ケース

- 問題入りスキルを使って AI に生成させただけで、人間が指摘なしに全テストが通ってしまう（必ず問題点の指摘・修正が必要な設計を維持する）
- 受講者が異なる手順を踏んで異なる結果になる（スキルが同一コードを出力することで統一を担保する）
- 問題入りコードと正解コードのビジュアルの差が目視で確認できないほど微小（学習効果がない）
- 問題入りコードのパフォーマンス差が静的解析で検出できないほど小さい（学習効果がない）

### 🔒 品質ゲート

- 正解コードのコンパイル時エラー 0 / 新規警告 0
- 正解コードで既存の自動テスト（EditMode / PlayMode）が pass
- 正解コードでビジュアルリグレッションテストが pass（差分なし）
- 問題入りコードと正解コードで、モバイル GPU 負荷静的解析の主要指標（レジスタ数 / 算術サイクル数）に測定可能な差異あり
- 問題入りコードでビジュアルリグレッションテストが fail（差分あり）

具体の検証手段（コマンド / スキル / 計測ツール）は Phase 2 (Inception) で plan.md に記述する。
